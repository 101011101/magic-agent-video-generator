The Orphaned Solver

State manager audit — is it properly built, what is missing, and were the defects structural or just bugs. Evidence is cited to file:line or to a recorded run. 2026-10-14.

The short answer. The state manager's data structure is built and correct. Its behaviour was never wired. The full designed engine — 22 atoms, 40 tool signatures, a backward-search solver — exists in the repo and no live pipeline imports a line of it. And the defects that make the videos bad are structural, not bugs: we fixed six real bugs today and the output quality would be unchanged.

Were the defects structural, or bugs?

This is the question that decides what to do next, so it is worth separating carefully. Of the fifteen defects found today, the split is clean — and it is not the split you would hope for.

Structural — design, not code

Cannot be fixed by debugging. Each is a decision, or a decision never made.

idwhat
PRD-010The PRD has no model for motion, action or temporal logic. Every atom is a property of a single still state. The product is video; the type system describes frames.
SM-100Tool selection is not derived from state. Models are module-level literals; the endpoint is a one-line ternary.

SM-103/10426 of 30 endpoints never called, including face-detection — a consequence of SM-100.

What is missing

missingconsequence, measured
Any logic or motion check117 recorded faults in pipeline A, zero about motion. Not because motion was right — because no check could fail. end_state_ok is false in 15 of 16 lighthouse shots while both pipelines called those frames acceptable.
A tool selectorOnly 4 of 30 endpoints used. The unused set is disproportionately the cheap transformation tools: image-background-remover (5cr, enables paste-back), face-swap-photo (10cr, addresses the 11 identity faults), character-replace/video-to-video (act on an existing clip — nothing acts post-clip today; a bad clip is re-rolled, never repaired).
Transformation instead of regenerationThe pointer is handed to an instruction editor, which regenerates every pixel. Measured elsewhere and recorded in multishot-video-practice.md: "chained edits compound drift". The recommended fix — mask inpainting plus paste-back — is in neither pipeline.
Validation of uploaded referencesAn upload is copied verbatim as the identity anchor. No face check, no crop, no resolution gate. A full-body photo with a 40-pixel face becomes the reference for the whole film. /v1/face-detection exists and is never called.

What follows from this

  1. Stop fixing bugs to improve quality. It will not work. The bug backlog is a money-and-robustness backlog.
  2. PRD-010 is the root. No motion model in the type system means no motion check can be specified, which means action adherence can never be verified. Everything else in the logic taxonomy sits downstream of it.
  3. SM-105 is the cheapest real win. Widen the pass-through guard. The best-scoring, cheapest run in the repo already uses it; it fires almost never.
  4. SM-100 unlocks the tool catalogue. 26 unused endpoints, several of them cheap transformation tools that directly address recorded faults. None can be reached until something selects tools from state.

What I am not claiming

  • The grandma result is one easy clip. Direction, not proof.
  • SM-102 rests partly on a secondary source for "instruction editors regenerate every pixel". HUNT-100 exists to measure it on our own stack. Not yet done.
  • RUN-001 is one sample per cell and runs at 1k, while production runs at 2k. A narrow result means repeat the arm, not that we have an answer. krea-2 cannot reach 2k at all.
  • Only 41% of recorded issues are logic-mode. Fixing logic addresses a real but minority slice of what goes wrong; the rest is appearance — wheel design, branding, lighting.
  • Four of my earlier numbers were wrong and are marked CORRECTED on The Litmus Ledger. Two larger claims were also wrong: chain-length is refuted, and "litmus solved prop scale" was a hardcoded string literal, not a measurement.
