Two fixes · the seam gate (A) and the retry stop rule (B)

Both were picked as the cheap, high-signal items out of the architecture review. One fix per settled pipeline: the seam gate in pipeline-state-graph (A), the keyframe retry stop rule in pipeline-memory (B). Both were implemented and calibrated entirely offline against the recorded runs — zero API calls, zero credits, nothing committed. 5 files changed, +174/−24.

Read this first. The original diagnosis of the seam gate was wrong, and so was the brief written from it. The broken term was not S; it was L. Details in the first section. The honest version of each fix, including what is still unverified, is at the bottom of each half.

A · the seam gate

current/prod/pipeline-state-graph/src/clips.js, plus its readers in src/page.js and run.mjs.

What was actually wrong

The old gate was one opaque boolean ANDing three terms: V in band, S/med ≥ 0.6, L < 1.0. Every continuous join in every run reported pass: false. Three separate defects, only one of which had been identified up front:

  1. Unsatisfiable L threshold. L < 1.0 was never met by any join in any run — the measured floor is 1.26. This single term vetoed all 7 continuous joins on its own, and is the whole reason pass was always false. The luma-offset fix in seamFix does work (L falls to 0.21–0.60× its raw value); the threshold was an aspiration written into the file header, never a measurement. Not in the original diagnosis.
  2. S had no upper bound. It tested S ≥ 0.6 only, so v1's S = 16.631 and v2's S = 2.852 — the two loudest failures in the dataset — passed the S check. The gate was structurally blind to jolts. Not in the original diagnosis.
  3. seam_ssim was recorded and never used. It is the term that actually separates good joins (0.992–0.995) from bad (0.956 / 0.809 / 0.434). Its absence is exactly why the comparison page had to read SSIM by hand and concluded the seams were fine while the gate said they all failed.
Correction to the review. The review claimed the gate "fails a perfect seam" at S = 0. It does not. S = 0 with jump = 0 means the handoff frame is byte-identical across the join — the duplicate frame the comparison page lists as still unfixed. The gate was detecting a real defect there; the fix is to name it, not to loosen it.

What changed

  • SEAM — the seven thresholds as one exported table, each with the measurement behind it as an inline comment.
  • seamVerdict({link,S,V,L,seam_ssim}) → {pass, faults, soft, terms}. Continuous and cut joins are judged on opposite rules. Hard faults (handoff lost, duplicate, jolt, failed cut) set pass:false; V/L drift goes to soft and leaves pass true, because clean joins already span most of that range.
  • headFit(prev, file, K=6) — new. Per-frame grey 160×90 mean-abs-diff between the previous clip's last frame and frame k of this one. Deliberately separate from analyze(), whose results land in run.json and must not carry pixel buffers.
  • seamFix(an, {fit, dup, tie}) — now drops a duplicated handoff frame, porting pipeline B's measured trimPlan rule. fit is optional; without it the behaviour is byte-identical to before.
  • Cuts are judged instead of returning null — a cut whose two shots still look alike (seam_ssim ≥ 0.5) did not cut. 5 of 8 joins per run were previously unjudged.
  • page.js renders per-term faults; cell highlighting now reads terms rather than three hardcoded numbers.

Limits — what is not verified

  • seamFix's duplicate detection has never touched real pixels. ffmpeg and ffprobe are not installed on this machine, and all run media is gitignored and absent (0 mp4, 0 png on disk). The logic was verified with injected fit arrays, 6/6. The dup 0.25 and tie 1.1 constants are inherited from pipeline B's measured trimPlan, not re-derived for A's 160×90 units. The first real run should check the new per-join duplicate_fix record and confirm drop lands where expected.
  • The cut criterion is calibrated but unexercised. No recorded A cut fails it; the "shots barely move" failure was observed in B. Confirmed to fire synthetically at ssim ≥ 0.5.
  • The calibration table itself is solid: it comes from the measures.joins values recorded in each run.json, which are tracked and on disk.

B · the keyframe retry stop rule

current/prod/pipeline-memory/src/keyframes.js, plus src/page.js.

What was actually wrong

The gate fired a 200-credit retry whenever corrections() returned anything at all, including fault classes a re-prompt cannot move. Two recorded retries came back strictly worse and were discarded (frame:06: retry worse (1.5 < 3), frame:02: retry worse (7 < 8)). But the replay found the more important defect:

The defect was not over-eager retrying — it was blind retrying. In 6 of the 7 no-help cases, the faulted entity's own anchor was not among the inputs. The gate re-prompted without ever showing the model the reference image that defines the thing it got wrong. Pure stop-rule tuning can only recover ~200 credits on this record; re-sourcing is where the value is.

What changed

  • faults(plan, entry, names) — classifies each unstable entity as missing / duplicate / size / look / state, split into REF (size, look — the fault names what the thing is, so it comes from a reference) and TEXT (names what the frame does, so a prompt can move it).
  • retryPlan(...) — the stop rule, evaluated before any spend. Artifacts only → never retry. REF fault whose entity has an anchor not already an input → retry with that anchor added, mirroring A's v3 re-source fix. TEXT fault → retry. REF fault with every reference already shown, whose entity+class already failed a retry this run → stop.
  • better(a1, a2, names) — replaces stableCount − 0.5·artifacts. Compares per-entity transitions (fixed vs broke), counts a new image flaw as a regression, keeps attempt 2 only when fixed > broke. Ties keep attempt 1 explicitly — it is already drawn and observed, nothing in the record prefers the later draw, and it makes replay deterministic. (The old code silently kept attempt 2 on a tie.)
  • The retry now goes through run.job with the augmented input list, so the cache signature changes when a reference is added.
  • run.log.keyframes[id].gate records fault classes, artifacts, retry/no-retry, why, what was re-sourced and the comparison — auditable the way A records forced. Surfaced on the run page.

Credits saved vs. help lost

Saved

  • 200 credits, 0 fixes lost. One skip (desert-tokyo/06) — and it is one of the two logged "retry worse" cases.
  • Both logged wastes are addressed: desert-tokyo/06 is skipped; lighthouse-v2/02 is re-sourced instead of repeated blind.

Changed, not yet quantified

  • 3 of 5 previously-blind retries now carry the missing reference. 1,000 credits that were being spent on a re-prompt that could not work are now spent with the anchor attached.
  • That is an expected-value change, not a saving, and it cannot be quantified without a paid run.

The one judgement call

The third clause. "Already retried this run" is a wash — it saves desert-tokyo/06 but throws away lighthouse-v1/06, which genuinely fixed Lamp. "Already failed a retry this run" separates them: Lamp:look was retried at shot 04 and succeeded, so shot 06 is still allowed; Coupe:look was retried at 03 and failed, so 06 stops. Chose the second, which is also closer to what A's controller.js:198 already tests — fault class persisting, not merely attempted.

Limits and corrections

  • "Size faults are never prompt-fixable" was too strong — that premise came from the brief and the replay contradicts it. Shell:size retries went 2/5 and Lamp:look 2/4: poor base rates, not zero. A flat ban on REF classes would have cost 3 real fixes, which is why the rule re-sources instead of refusing. The only class that is 0-for-3 is artifacts (Visible storefront text and logos came back verbatim every time), so that is the sole unconditional refusal.
  • Pre-existing bug, inherited not fixed: corrections() treats count > 1 as a duplicate for every entity, so the plural Pedestrians entity with count: 3 is flagged "drawn 3 times; it must appear once". The new classifier inherits it, but only in the permissive direction (duplicate → TEXT → retry), so it never causes a wrong skip.
  • Fixed in passing: page.js printed undefined for unstable entities — c.unstable.map(u => u.name) over an array of plain name strings.

Status

  • 5 files changed, +174/−24, all five parse clean under node --check. Nothing committed, nothing pushed — the changes sit in the working tree on docs/readme-tree-and-vision.
  • Neither pipeline can be run on this machine until ffmpeg is installed; both depend on it for every clip operation. That, not the fixes, is the blocker on confirming A's duplicate drop against real pixels.
  • Next paid run should be a cheap probe (--beats 2 on A, --scenes 1 on B) to exercise duplicate_fix and the gate record, not a full 9-clip run at ~8,000 credits.
