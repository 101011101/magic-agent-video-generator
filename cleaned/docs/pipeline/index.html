Keyframe pipeline: flow, logic and schemas

From a natural-language prompt to slides. Models write and check; code keeps the state. Nothing is painted until the plan is clean.

Who runs it

node cleaned/run.mjs is a plain script: code decides every step, the order, the loop count (at most 2 question rounds) and the gate. LLM calls are function calls inside fixed steps that return JSON; no model decides what runs next. Nobody steers it while it runs; Claude only watches the log.

State manager rules (code)

  1. A frame's row is the ids requested for it, plus its environment. By induction every requested asset is in its frame. No model writes a row.
  2. The base of a slide is the latest row that contains its environment; an asset entering a frame comes from the latest row that contains it; its sheet is used only the first time it ever appears.
  3. A prop used at a place without being brought in, and never seen elsewhere, was always there: it joins that place's initial contents (painted into the plate). Characters are never assumed.
  4. Held props move with their holder; contents move inside their container; things packed in a fixture are part of its place; things on a part come with its owner.
  5. A prop seen elsewhere must be carried in; "appear" is only allowed after "vanish"; a character on screen must exit before it is somewhere else.
  6. Every asset the id pass tagged is on screen somewhere; nothing on screen is untagged.
  7. Each finding becomes a question for the editor; images wait until there are none.
